# 写作蒸馏文字流程验收

方法真源：<https://github.com/larashero3-dotcom/writing-dna-skill>，本次固定版本 `9e780d0ea9fda9937149148a3103f181eed43326`。原始 Skill、模板、MIT 许可证、去 AI 痕迹规则及逐文件校验值保存在 `app/prompts/writing-dna-upstream/`，不使用无法验证的“风格还原百分比”。

## 现在的执行顺序

1. 全文入库，先用脚本统计词频、名词、动词、副词、句长及排版标记。词性由 jieba 标注，英文未分类单独列出。
2. 一篇一次请求精读。长文在同一篇内分段，保留连续位置和每段全文；不会把八篇合成一次观察。每篇有元数据、开头、转折、正文环节、结尾、四类阅读笔记和可执行规则。
3. 逐字核对结构引用、规则证据。找不到原句的规则被剔除并保留拒绝原因；结构引文不成立或全部证据不成立时不通过。
4. 独立归纳语言、结构、选题/素材/认知。每条规则附适用边界、支持原句及可找到的反例。大量语料采用有证据的分层归纳，原始逐篇笔记仍完整保留，不截去全文。
5. 生成四份分层 Markdown 和不超过 4000 字的 `Writing-DNA.md`。没有图片时明确视觉资料未验证，只统计真实文本标记。
6. 用五份产物盲写新稿，再用另一次请求对照完整原文检查。报告公开成稿、评分、比较片段、理由和局限。模型辅助自检不是人工风格验收。
7. 保存为灵魂时保存完整分层产物；写作时读取五份产物和体裁/题材相近的五篇完整原文，不再按 8000/30000 字静默截断。用户修改过的提示词优先于旧运行的整合文档。写作提示中同时载入来源 Skill 的白名单去 AI 痕迹规则。

## 结果状态

- 少于 20 篇：样本暂定，不称稳定作者模型。
- 语料确实不足三种体裁、三条跨篇命题或复刻未达 7 分：列出待验证项，不凭格式或字数冒充质量通过。
- 文字检查项通过：只表示自动检查通过；图片和人工验收始终另列。
- 网络超时、5xx、响应不完整：保留回执和每阶段检查点，未知结果不自动再次收费。明确失败可点击继续；请求结果未知须先在运行记录处理。

报告提供“灵魂提示词 / 逐篇精读 / 分层产物 / 复刻检查”四个视图。“下载完整产物”导出 ZIP，包含五份 Markdown、raw 全文、_meta 逐篇笔记、跨篇规则证据和质量检查。

旧报告仍可读；“按新版重新蒸馏”使用已有全文执行新流程，不重复采集、转写或向素材库导入。

## 部署依赖

使用工作台已配置的 Python（`STUDIO_PYTHON` 或采集配置）。除采集既有依赖外，安装：

```powershell
python -m pip install -r app/requirements-dna.txt
```

缺少词性统计依赖会返回真实错误，不用模型编造词频。所有模型请求使用“素材提炼”当前分配的 API，支持现有 Chat/Responses 适配。逐篇精读的请求数多于旧批处理，代价是换取完整覆盖和可追溯证据。
