# AI 内容生产基地｜产品需求文档（PRD v1.1）

> 项目代号：AI Content Studio  
> 产品属性：个人私有内容生产系统，桌面网页优先  
> 文档日期：2026-10-26  
> 当前阶段：需求确认版 / P0 原型实施依据  
> 设计原则：复用 AIHOT 信息引擎、用户现有抖音采集与飞书素材、Chzhinan；写作由用户自定义提示词主导，使用 dontbesilent Skills 进行按需诊断与审核。

## 0. 一页结论

**产品不是通用聊天机器人，而是从信息输入到内容发布的生产基地。** 用户可以每天阅读 AI 行业资讯，也可以导入自己积累的文案/蒸馏文件，选择一个自己配置的写作模板，自动检索绑定知识库，生成 X 短帖、X Thread 或视频口播稿；之后交给一组按需启用的审核 Skill，用户在差异对照中批准修改，形成最终稿，并把发布表现沉淀为下一次创作的依据。

**主闭环：** AIHOT 情报 / 飞书素材 / 手动想法（三选一或合并）→【直接写 X / 先找选题再写 / 先收藏研究】→ 选择写作模板 → 自动检索绑定知识库、核对情报事实和硬性规则 → 生成草稿 → dontbesilent Skills 按需审核 → 用户局部修改定稿 → 复制或经授权发布 → 表现回填与经验沉淀。**选题不是必经步骤。**

**第一版成功标准：** 同一条真实 AIHOT 新闻可分别走通「一键直接生成 X」和「先衍生选题后生成」两条路径；能导入真实蒸馏资料、复用 Prompt/硬规则、按需审核并保存定稿；每条内容保留事实和知识来源。

## 1. 背景、定位与边界

### 1.1 为什么开发

- 已有 AIHOT（AI 行业信息采集、筛选、聚类、日报）、抖音素材采集流水线（视频/口播/评论/飞书回填）、Chzhinan 文案 Skill 与作者蒸馏，以及大量存在飞书的同行和跨行业写作素材。
- 当前缺的不是素材数量，而是统一入口、知识使用规范、可配置写作策略、发布前审核和发布后反馈闭环。
- 真实创作方向以 AI、AI 工具、AI 编程/产品实践为主；首要发布平台 X，随后复用选题生成视频口播。

### 1.2 用户画像与目标

- **唯一主要用户：** 系统拥有者本人；可能由受授权的开发 Agent 维护。首版不做面向公众的账户/会员/计费业务。
- **主要场景 A：** 看 AIHOT 最新 AI 资讯，单击「直接生成 X 短帖」立即进入写作；或单击「衍生选题」生成不同角度，再选一个写。无需先收藏或建立选题卡。
- **主要场景 B：** 在飞书/本地上传一份蒸馏写作指南 → 自定义提示词和硬性规则 → 用该模板持续创作。
- **主要场景 C：** 提交自写草稿 → 不改写原稿先执行 dbskill 审核 → 选择性修订。
- **主要场景 D：** 根据抖音视频/评论的用户问题选题 → 结合 AI 行业资料出内容。

### 1.3 非目标（P0 不开发）

- 不重做 AIHOT 已成熟的 RSS、X/公众号采集、热点和日报算法。
- 不复制另一个完整的抖音采集器或视频剪辑工具。
- 不做自动发 X、抖音或公众号；P0 支持复制成稿、保存发布记录与手动回填数据。
- 不做商业 SaaS 的多租户、积分、支付、客服或插件商店。
- 不默认启用所有 dbskill；不把他人的写作风格当成唯一正确标准。
- 不把 AIHOT 公开 API、RSS、MCP 直接变成私人知识库出口。

## 3. 端到端主流程

**步骤 1 — 收集：** AIHOT 负责新闻/观点来源；抖音脚本负责视频、口播和评论需求；飞书和 Markdown 用导入/同步进入私有素材层。来源存储时明确 source_type、source_id、原链接、作者、发布时间、采集时间、使用许可与可公开性。

**步骤 2 — 筛选：** AIHOT 的新闻归组与热度只应用于情报，不强制套用到永久有效的营销文案或作者蒸馏知识。素材去重后分为「事实情报」「外部写作案例」「个人原稿/经验」「蒸馏指南/规则」。

**步骤 3 — 决定创作路径（不强制选题）：** 从 AIHOT 情报可直接生成 X 短帖/Thread/口播稿，也可先生成多个选题角度后再写，或仅收藏入素材库；从飞书文案和手动想法进入时也提供相同选择。直接写作时自动建立轻量关联记录，无需用户手动创建选题卡。

**步骤 4 — 配写作模板：** 选 X 短帖/X Thread/视频口播、写作提示词、绑定知识集、强制规则、可选文风/作者 DNA、检索设置。生成前展示将使用哪些知识集、提示词版本与预估模型调用，允许用户排除某项来源。

**步骤 5 — 检索与写作：** 系统先搜索事实，再检索案例与方法，组装经过标注的上下文；AI 依据用户模板写作，同时保存引用映射和生成版本。没有事实支持的断言标记为「待核实」，不能伪造体验或实测数据。

**步骤 6 — 审核：** 初稿完成后按模板自动或手动调用匹配的 dontbesilent Skill（可多项，但不强制全部）。每个结果输出问题位置、理由、严重程度和最小改法；主审核台合并去重，不自动覆盖文稿。

**步骤 7 — 审改与定稿：** 用户选择逐条接受/忽略，或请 AI 按选中问题执行局部修订。显示修改前后差异。硬性规则再次校验，确认后定稿。

**步骤 8 — 发布与反馈：** 一键复制 X 短文或 Thread，保存发布日期、链接、曝光/互动/关注/咨询等手动指标。复盘仅能提出待验证的写作假设；经过确认的有效经验才能写入知识库规则。


### 3.1 三个入口，一套创作引擎（P0 必须实现）

**入口 A｜从 AIHOT 新闻直接创作。** 用户正在读 AIHOT 的最新资讯、热门事件、主题页或详情页时，看到原文、发布时间、信息来源和事件摘要。每条情报统一提供「直接生成 X」「衍生选题」「收藏到知识库」三个操作。直接生成 X 时，弹出轻量创作配置或进入创作室：默认选中「X 新闻速评」模板，自动携带情报 ID、事实摘要及原始链接，执行检索、生成、审核与定稿。**不能要求用户先收藏、先建立选题卡才能写。**

**入口 B｜从素材库创作。** 从飞书历史文案、抖音转写、作者蒸馏报告或 Markdown 中勾选一条或多条素材，点击「创建内容」。可先提出选题，也可使用现成话题直接写。外部作者文字只用于研究结构和观点，不能冒充本人事实。

**入口 C｜从空白想法创作。** 用户输入一句话或粘贴草稿，例如「最近的 AI 编程 Agent 为什么改变小团队开发」，选择「找选题」「直接写」「只审核现有稿」之一。没有实时新闻时也能用绑定知识库写长期有效内容。

**三入口统一：** 无论从哪里开始，均建立 `studio_content_job`，记录 `entry_type`（aihot_news / asset_library / manual_idea）、`source_refs`、`intent`（direct_write / topic_explore / audit_only）、`template_version`，进入相同的检索、生成、审核、修订和发布记录链路。一个新闻可以关联多篇不同角度的内容，也可以只形成一条直接生成的短帖。

### 3.2 AIHOT 新闻卡的动作与页面流转

| 在 AIHOT 资讯上点击 | 系统立即执行 | 用户看到的结果 | 下一步 |
| --- | --- | --- | --- |
| **直接生成 X** | 携带资讯事实、来源和关联事件；加载默认 X Prompt、绑定库与规则 | 可编辑 X 短帖草稿；旁边显示核对过的新闻事实和参考资料 | 审核 → 局部修改 → 定稿 |
| **生成 X Thread** | 使用同一新闻证据，生成多帖结构并逐帖检查长度 | 可编辑的连续多帖 | 审核 → 复制/手动发布 |
| **衍生选题** | 查新闻事实、过往相似选题、知识库文风案例、个人经验 | 3–5 个角度卡：核心观点、目标读者、证据、限制、推荐体裁 | 选一个 → 再选择 X / Thread / 视频稿 |
| **收藏到素材库** | 建立引用和收藏记录，不自动调用写作模型 | 素材库中可搜索到的资讯及标签 | 任意时候再发起创作 |

**默认行为：** 当用户明确点击「直接生成 X」时，不强制输出 3 个选题或重复提问。只在存在影响真实性的关键事实缺口时提示补充；新闻正文、模型事实依据和作者风格样本使用不同证据标签。

**AIHOT 数据边界：** 保留其新闻列表/热点/事件归组逻辑。创作入口读取真实情报记录并带上稳定 `source_id`，而不是将网站 HTML 文本简单复制为一篇没有出处的新文章。新闻有新进展时可重新生成，但历史内容任务的事实快照保持不变。

### 3.3 写作引擎的固定规则

1. **根据用户点击的目的选择任务：** 直接写、先找角度、仅审稿是三种不同任务，不把它们强行串成一条固定模板。
2. **先核实“写什么”，再决定“怎么写”：** AIHOT 官方来源/可靠情报用于事实；本人经历用于个人主张；飞书优秀文案与蒸馏库用于角度、结构、表达；外部作者的经历不进入本人成稿。
3. **写作模板是主控件：** `Prompt + 知识库绑定 + 硬性规则 + 审核预设` 组成完整写作配置。不同的 X 新闻速评、个人观点、X Thread、视频口播可以保存不同模板。
4. **审核在生成后按需触发：** X 短帖不默认调用口播 Skill；dontbesilent Skills 返回原句定位和具体建议，用户决定接受、忽略或局部重写，不得整稿无授权改写。
5. **每一步都能回看：** 资讯来源、选题候选、所用知识片段、Prompt 版本、各稿版本、审核问题、发布链接和表现应关联在同一个内容任务；AI 结论与已验证规律分开。
6. **原本的公开站与私人创作必须隔离：** 新闻可来自 AIHOT 公共数据，蒸馏库、草稿和个人 Prompt 永不进入公共 RSS、API 或 MCP。

### 3.4 两条 P0 核心端到端验收路径

**路径 A：新闻一键生成。** 打开 AIHOT 一篇真实资讯 → 点击「直接生成 X」→ 自动加载「X 新闻速评」提示词与绑定蒸馏库 → 展示新闻事实及参考材料 → 一次生成可编辑短帖 → 按需触发审核 → 局部接受改动 → 定稿与复制 → 发布链接/效果回填。整个过程**不必创建选题卡**。

**路径 B：新闻衍生多个选题。** 打开同一篇资讯 → 点击「衍生选题」→ 生成多个受众/观点方向 → 选择其中一个 → 指定 X 短帖、Thread 或未来的短视频口播 → 加载相应模板和知识库 → 创作、审核、定稿和归档。每个方向保留对同一新闻的来源关联，但各有独立稿件与版本。

**其他可用路径：** 从飞书/抖音/Markdown 素材直接发起同样流程；没有新闻时从手动想法开始；已有草稿可跳过创作直接进入审核。

## 4. 模块 A：信息情报与采集接入

### A1. AIHOT 改造原则

- **保留：** 原有 RSS、网页列表、JSON、X 账号、公众号及外部推送采集；预筛、双评分、内容写作、事件聚类、热点、报告、预算熔断与 pg-boss Worker。
- **新增：** 私人内容工作台可读取「情报快照」，把精选条目或事件转换成 Topic Draft；添加“与个人账号写作方向的关联度”这一独立评分（非替换 AIHOT 热点分数）。
- **隔离：** 私人知识、写作稿件和未发布观点永不进入 AIHOT 原有公共 publication/RSS/API/MCP 路径。私有入口需认证。
- **区分：** 热点事件的“很多人都在报道”和值得本人写的“有独立观点与资料依据”是两个指标。

### A2. 用户已有抖音采集模块

- 现有仓库 `douyin-material-pipeline` 提供链接/主页采集、互动数据、音频转写、飞书推送、评论蒸馏和需求主题聚类；保留脚本内部逻辑，不重写采集器。
- P0 通过单独的导入适配器读取该流水线导出的 JSON/CSV/Excel 或飞书结果；P1 再以任务形式触发脚本并获取任务进度。
- 将 `play_count` 缺失记录为未知，不得把脚本中的点赞折算值显示为平台实测播放量。
- 采集失败、登录态失效和反风控问题必须原样提示任务状态，不静默返回空成功。

### A3. 飞书和文件导入

- P0 支持导入 `.md/.txt/.docx/.csv/.xlsx/.json/.jsonl`；保留完整原文、文件哈希和文档版本。
- 飞书原本的三张写作生产表以配置映射接入，不在代码写死表 ID/字段名；首版支持导出文件导入，P1 增量同步记录 `record_id`、更新时间和删除状态。
- 导入预检显示文档数、有效数、重复数、缺正文数、字段映射错误数；只有用户确认后落库。
- 外部内容可用于内部研究与参考，但是否允许全文转载、发布或作为模型训练集单独标注。

## 5. 模块 B：知识库与蒸馏资产

### B1. 四类知识集

| 类型 | 内容 | 可承担的角色 |
| --- | --- | --- |
| 事实库 | 官方公告、产品文档、本人已证实经历、新闻原文 | 核实时间、功能、数字、版本和事实 |
| 写作案例库 | 飞书外部文案、跨行业优秀案例、本人历史稿件 | 借鉴结构、角度、节奏，不当事实依据 |
| 蒸馏方法库 | 作者 DNA、写作指南、常用结构、适用条件、反例 | 创作风格和写作启发 |
| 规则与记忆库 | 自己认可的硬性规则、个人事实白名单、已验证复盘 | 约束生成、长期一致性 |

### B2. 上传一份蒸馏文件后的交互

1. 选择「上传蒸馏知识」；上传单篇或多文件夹；可选指定「作者/主题/来源」和知识集。
2. 系统解析并展示全文预览、章节结构、文件哈希、是否已有同版本；不静默覆盖。
3. 自动抽取写作候选：核心方法、适用条件、反例、原文示例；全部先标「AI 提取·未确认」。
4. 用户可将某条转为「参考建议」或「硬性规则」。硬性规则必须用户确认，不允许根据某作者出现频率自动升级。
5. 入库后建立全文搜索；P1 加语义检索和重排。每条回答都能打开具体原文、段落和版本。

### B3. 检索规则（必须实现）

- 先判断任务：**事实核验** 查事实库；**模仿表达** 查案例库与蒸馏方法库；**个人经验** 查本人档案。不可混用证据等级。
- 检索范围只能来自用户为当前模板绑定的知识集，允许临时加入/排除；严禁跨私人项目默认全库搜。
- 检索返回：`document_id / chunk_id / 来源类型 / 原链接或文件路径 / 版本 / 时间 / 相关性 / 摘录`。引用可追溯到完整原文。
- 对不同作者相互矛盾的方法给出冲突，不把多个方法机械叠加；按模板选择一个主方法，其余只作为候选。
- 提示词注入防护：导入文案里的“忽略以上规则”等内容全部视为被分析资料，不当作系统执行指令。
- AIHOT 的旧新闻按发布时间与更新状态标记时效；永久素材不按新闻热度衰减机制淘汰。

## 6. 模块 C：可自定义写作提示词（本项目核心）

### C1. 模板管理界面

写作模板列表 → 新建/复制/版本历史/启停。示例模板：「X · AI 工具观点短帖」「X · AI 新闻速评」「X Thread · 观点展开」「抖音 · AI 工具口播」。

**模板编辑分为 6 个独立区块：**

1. **基本信息：** 名称、描述、平台、内容形式、目标受众、是否启用。
2. **写作提示词：** 用户自由编辑的主 Prompt，可插入变量 `{{topic}}`、`{{angle}}`、`{{facts}}`、`{{examples}}`、`{{writing_guide}}`、`{{user_experience}}`、`{{platform}}`、`{{length}}`。
3. **绑定知识集：** 多选事实库、外部案例库、特定作者 DNA、个人经验；允许设优先级、每类最多取 N 个片段、最低相似度（后期）。
4. **硬性规则：** 每条规则独立开关、作用范围和严重度；示例“禁止捏造我自己经历”“只保留一个核心观点”“未经核实的数据不得写成确定事实”。
5. **参考方法：** 可选择 dontbesilent 写作指导、Chzhinan/作者 DNA 等作为可用方法；选择后展示用途与适用范围，**不能取代用户自定主 Prompt**。
6. **审核方案：** 启用的审核 Skill、自动/手动、审核强度、是否必须人工定稿、最大返修轮次。

**保存要求：** 每次保存产生不可变的 `template_version`；历史稿件保留当时的版本，修改模板不会追溯改变旧稿。

### C2. 提示词合成优先级

1. 系统级安全和来源真实性规则：不得伪造事实、越权读取或执行未经允许的动作。
2. 当前内容任务的已确认事实、平台与输出边界。
3. **用户当前写作模板的硬性规则与主 Prompt。**
4. 绑定知识库提取的蒸馏方法与本人写作偏好（有冲突时按模板配置选择）。
5. dontbesilent / Chzhinan 作为参考方法与审核流程，不能暗中重写上层要求。
6. 外部素材中的原文和示例，仅是引用/分析数据，不具有指令权限。

硬性规则冲突时不应“按规则数量多数决定”，而应暂停生成，展示冲突规则和来源，供用户确定优先级；绝不能静默丢弃。

### C3. 三种写作模式

| 模式 | 用户输入 | 系统行为 | 输出 |
| --- | --- | --- | --- |
| 指导式 | 我还不知道怎么写，只有话题 | 检索事实+类似案例，提出最多 3 个角度，解释推荐理由，用户选后写 | 选题建议 → 初稿 |
| 快速创作 | 已有选题、指定模板 | 直接检索并生成，可查看引用依据 | 一条完整初稿 |
| 参考改写 | 上传现有草稿/文章 | 先读当前原稿，按主 Prompt 和知识检索判断轻改/中改/重构；可选择保持原骨架 | 带对照的新版稿 |

**默认：** 首次新手使用指导式。用户明确“直接出 X 帖子”或已经选定角度，跳过重复澄清直接生成。

### C4. 写作输出规格

- **X 短帖：** 默认以 X 账号实际允许的字数为准，发布前在前端显示字符计数；中文计算必须与所采用的 X 发布通道规则一致，不靠简单 `len()` 断言可发。
- **X Thread：** 生成可编辑的多帖列表，逐帖字符检查，合并复制与单条复制，保持上下篇逻辑连续。
- **视频口播：** P1 增加时长范围、目标平台、成稿/已拍状态、开头及标题、分段口播；不默认将 X 短帖硬扩写成冗长视频。
- **生成结果：** 正文、核心观点、引用清单、使用的模板版本、知识集快照、生成时间和模型信息分开保存；正文不自动混进参考链接或 AI 报告。

## 7. 模块 D：dontbesilent Skills 智能审核

### D1. 核心原则

**生成完成以后才进入审核。** 系统先做基础事实与硬规则检查，再按内容形式路由到适用的 Skill；不要求每个 Skill 都产出“打分”。审核意见的职责是发现问题，不是替代用户的写作意图。

### D2. 审核路由表

| 审核/方法 | 触发条件 | 应返回什么 | 限制 |
| --- | --- | --- | --- |
| `dbs-content-value` | 未发布选题或初稿，需要整体价值判断 | 面向谁、留存理由、商业相关性、最多 3 项改进方向 | 不虚构浏览量或流量预测 |
| `dbs-resonate` | 文稿已写成，检查共鸣 | 原文定位、核心观点、共鸣缺口、删改建议 | 不负责最终改写 |
| `dbs-script-flow` | 视频口播文稿 | 衔接、信息密度、口播问题及原句建议 | X 短帖不默认调用 |
| `dbs-ai-check` | 发布前检查机器化表达 | 按句定位“AI 味”，给严重度和解释 | 不是 AI 文本检测器，不能判定作者身份 |
| `dbs-content-risk-check` | 发布前、平台有敏感风险 | 逐句平台风险、可能触发点和最小修改方案 | 不承诺平台审核通过 |
| `dbs-title-cover-intro` | 视频、图文需要标题/开头 | 标题、封面文字、开头建议 | X 短帖不默认生成封面 |
| `dbs-plain-writing` | 用户要求产品说明、工具说明、非营销描述 | 直接且准确的说明文 | 不应强制覆盖观点类短帖 |
| `dbs-spread` | 发布后有实际传播结果 | 解释可能传播的机制与证据不足处 | 不把相关性当因果 |

**建议默认审核预设：** X 短帖 = 事实/硬规则 + `dbs-ai-check`（按需）+ `dbs-resonate`（按需）+ 发布风险；X Thread = 再加结构与连续性通用检查；视频口播 = 加 `dbs-script-flow`；单纯产品说明 = 使用 `dbs-plain-writing` 而非先套营销公式。所有预设可按模板修改。

### D3. 审核数据与交互

- 审核返回结构化 `issue_id, skill_id, quoted_span, location, severity, explanation, suggestion, evidence, status`；必须有引用位置，找不到位置的意见归“整体建议”。
- 不同 Skill 针对同一句的重复意见合并；保留原始审核报告与运行时间，最终页面只显示合并问题卡。
- 用户操作：**接受建议 / 忽略 / 按此局部改写 / 再次审核 / 查看原报告**。接受建议只改对应文本片段，不覆盖其他内容。
- 每次改写生成新版本，展示 diff、来源与改动原因；旧版本可恢复。审核之后如果用户手动调整了文字，相关审核标记为“待重新验证”。
- 高风险事实错误、明确违反本人硬性规则时阻止一键「审核通过」；平台风险和风格建议可由用户确认并承担发布判断。
- 自动审校默认最多 1 轮自动建议，不开启 AI 自己不断循环重写；额外改写由用户触发，以控制成本和跑偏风险。

### D4. Skill 版权与版本

- dontbesilent/dbskill 当前仓库许可证为 **CC BY-NC 4.0**。涉及推广个人商业产品、商业经营内容或商业服务时，不得直接假定满足非商业使用条款；正式集成与持续商用前需要取得适当授权或改用自主实现的同类审核规范。
- Skill 文件作为版本化依赖保存来源 URL、SHA/版本、许可、启用状态和对应参考文件；不可直接复制后改名冒充自研。
- 不允许导入的外部 Skill 自动读取服务器密钥、开放生产数据库写权限或向第三方发送私人语料。

## 8. 模块 E：选题、稿件与发布复盘

### E1. 选题卡

字段：`topic_id, title, core_question, target_audience, hook_candidate, angle_options, fact_source_ids, example_source_ids, owner_note, state, created_at`。

状态：`待研究 → 待确定角度 → 可写 → 写作中 → 已成稿 → 已归档`；同一资讯可以衍生多个选题，但不能每次都重复创建同名卡。

### E2. 内容任务与版本

状态：`草稿 → 待审核 → 待人工确认 → 已定稿 → 已发布 → 已复盘`，另有 `失败/已取消`。支持手动新建草稿，跳过情报阶段。

每条内容永久保存：关联选题、选中来源、写作模板版本、知识快照、每版正文、审核意见、用户修订、定稿、发布平台和链接。

### E3. 发布与结果回填

- P0：复制 X 短帖/Thread；用户手动填发布时间、URL、曝光、点赞、回复、转帖、收藏、关注/私信/线索（能取得的填，不能取得的不填）。
- P1/P2：研究 X 正式 API 和授权后，再决定直接发布、定时发布或自动取数据；不对用户承诺现成能力。
- 对比同一账号同一时期的历史基线；如果没有曝光、账号基线或对照样本，输出“无法判断具体传播原因”。
- 复盘结论以「事实」「推测」「验证结果」三类存储；未经用户确认不得把推测自动写入硬性规则。

## 11. P0 页面交互与验收

| 页面 | 核心交互 | 可验收条件 |
| --- | --- | --- |
| 情报列表 | 查看原文、直接生成 X、衍生选题、收藏素材 | 同一真实情报可一键直出 X 草稿或生成多个选题，均保留来源 |
| 素材库 | 上传/预检/确认、全文查看、关键字查询 | 30 份样本完整导入，去重/来源信息可核验 |
| 写作模板 | 自定义 Prompt、绑定库、硬规则、审核预设、版本保存 | 保存两个模板后，相同选题产出不同体裁且模板快照准确 |
| 创作页 | 输入选题、检索预览、生成、多版对比 | 可查看至少 3 条被检索的相关素材及原文出处（资料不足明确提示） |
| 审核页 | 自动/手动 Skill、逐条问题、接受/忽略、diff | 修改一处不会无故改动未选中的其余内容 |
| 作品档案 | 定稿、复制、关联链接、人工指标、复盘 | 下次能从历史稿还原模板、素材、审核及修改记录 |

### P0 必测端到端用例

1. **上传蒸馏档案 → 绑定写作模板：** 用户上传一份包含多条写作规则和真实原文的 MD，预览并确认；建立 X 模板，绑定知识集，选择一条硬性规则，能看到来源。
2. **AIHOT 情报 → 直接生成 X：** 在一条真实 AIHOT 情报上直接点击「生成 X 短帖」，不经过选题页，即可按选定 Prompt 和绑定知识库生成可编辑草稿，保留原文链接、核验状态与规则执行记录。
3. **AIHOT 情报 → 多角度选题 → X / 口播稿：** 对同一条情报点击「衍生选题」，生成 3–5 个不同目标受众/观点的选题；选择一个生成 X 短帖、Thread 或视频口播（视频在 P1 开发）。
4. **审核 → 局部修改 → 定稿：** 审核找到至少一条模拟问题，用户接受其中一项，diff 仅改变该处，其余正文不变；再次检查硬规则后定稿。
5. **私人数据保护：** 未登录请求所有 `/api/studio/*` 都拒绝；AIHOT 公开 RSS/API/MCP 不能读到导入的飞书全文和未发表稿件。
6. **失败恢复：** 同一个写作任务重试不重复扣费；Worker 重启后任务状态可恢复或明确失败；用户取消任务不会得到伪成功稿。
7. **复盘回流：** 定稿与发布链接、数据快照关联；产生的 AI 建议仅写为待验证结论，不自动升级成硬性规则。

> 首先只实现 P0-A，给出差异文件清单、现有接口可复用清单、数据库迁移草案、私人权限隔离测试，以及可以运行的本地验证地址。任何修改生产代码、付费模型调用、外部推送、自动发布和删除数据都必须预先明确授权。先执行 `npm run typecheck`、适用的测试和 smoke 验证，再提交后续阶段。
