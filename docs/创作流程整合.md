# 创作流程整合

工作台围绕一次创作的数据交接组织，不把各仓库页面并排嵌入。采集、提炼、模板、灵魂、知识库、稿件、检查与版本使用现有持久对象串联；页面入口只是同一流程的不同起点。

| 原项目能力 | 工作台职责 | 数据交给下一步 |
| --- | --- | --- |
| douyin-material-pipeline | 采集、转写、来源与互动数据、飞书与导出 | 原始作品与有版本的案例文档 |
| AIHOT | 情报筛选、来源留存、衍生选题 | 选题和来源快照 |
| Hermes | 用户提示词、灵魂提取、内置人格规则、黄金三秒与文案类型 | 版本化写作模板、个人灵魂及本次写作配置 |
| Chzhinan | 作者习惯、语言表达与真实原文分层参考 | 提炼规则需有原句依据；正式稿同时参考相关完整样本 |
| dbskill | 原稿生成后的诊断、逐处修改、重新检查 | 问题、用户处理决定、检查所对应的正文版本 |

Hermes 内置灵魂规则与提取提示词直接读取原 server.js 的默认文本，不重新编造替代规则，也不启动额外页面。Studio 负责用户模板、知识范围和规则的组合；当前模型与 Hermes 原生 bridge 都读取同一份 draftContext。当前适配不是原项目全部多次模型调用流程的逐项搬迁。

从采集起步：选本批有正文的作品 → 沿用 prepare-writing 去重入库 → 选择学习样本与要求 → 提炼 → 核对原句、编辑系统提示词 → 保存模板与个人灵魂 → 输入选题或粘贴原稿 → 查看实际模型上下文 → 生成 → dont 方法检查 → 人工修改、复检、定稿。

从创作起步：选择已有模板 → 输入选题或原稿。模板的知识库与灵魂自动带入，可在本篇覆盖。稿件创建时保留模板快照、灵魂规则和相关完整样本；模型请求及生成版本记录实际知识片段与来源快照。不在每篇写稿时重新提炼作者。

提炼的 taskRun 保存样本 ID、哈希、要求、模型响应和原句证据；方法文档保存灵魂与提示词；模板关联方法文档和原始样本；稿件关联模板快照；检查绑定正文与写作配置哈希。这些关联用于恢复、复用与失效判断，不额外制造一套互不相通的资料库。

少量样本只形成当前样本的临时写法。这里没有执行 account-distill 的完整作者研究、独立留出验收、完整 Writing DNA 多文件产物流程；不能将此工具接通表述为已完成某作者的正式蒸馏。新增提炼请求不会自动重试未知结果。飞书同步与 Markdown 导出是资料保存分支，不是写作的前置步骤。
