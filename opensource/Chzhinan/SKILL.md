# 素材库 / 作者 DNA 驱动的口播改写

本 Skill 只做一件事：

**把一篇已有参考文案，改成更适合当前任务、可以直接口播的新文案。**

它不是机械洗稿，也不是强制套某个爆款公式。

最终原则：

> 原稿负责“这次到底要讲什么”，作者 DNA 负责“这个作者通常怎么写”，真实样本负责“验证当前这次该不该这么写”。

---

## 1. 两种模式

### 模式 A：普通素材库改写

用户没有指定作者。

流程：

参考文案
→ 拆解
→ 选题与借势库理解母问题
→ 爆款文案拆解库检索
→ 精读 3–5 篇候选完整原文
→ 按需选择 0–2 个改写组件
→ 原稿与候选比较
→ 自动决定轻改 / 中改 / 重构
→ 生成初稿
→ 去 AI 味
→ 最终核验
→ 输出

### 模式 B：指定作者改写

用户明确说：

- 按跨海改
- 用跨海的写法
- 作者 = 跨海
- 用 writing-kuahai
- 按某个已经蒸馏好的账号写

流程：

参考文案
→ 确定目标作者
→ 加载 writing-{author}
→ 可用时加载 writing-dna-skill 产物
→ 判断当前内容类型
→ 在三张生产表中筛选该作者
→ 精读最相关的 3–5 篇完整原文
→ 按需选择 0–2 个改写组件
→ 原稿 / 作者 DNA / 真实样本三方比较
→ 自动决定轻改 / 中改 / 重构
→ 生成初稿
→ lieflat-less-ai-tone
→ Author Authenticity Audit
→ 输出

## 2. 核心选择原则

### 2.1 不为了改而改

素材库、作者 Skill、Writing DNA 都只有“参与比较”的资格，没有强制修改权。

如果原稿某一部分已经最适配当前任务：

**保留。**

### 2.2 也不为了保留而保留

如果原稿存在明显问题：

- 开头承诺不兑现
- 逻辑断裂
- 中段重复
- 论证不足
- 口播不自然
- 结构明显不适合当前受众

允许局部重构甚至整体重构。

### 2.3 高频不是公式

不得因为：

- 某种 Hook 出现很多
- 某个结构互动高
- 作者经常这样写
- AI 字段标了“可复用”

就直接采用。

最终判断始终基于：

当前主题 + 当前受众 + 当前事实 + 当前目标 + 当前内容类型。

### 2.4 局部最优必须服从全文

一个很强的开头、转折、金句或结尾，如果放进全文后造成：

- 人物状态不一致
- 语气跳变
- 观点强度失衡
- 信息密度断层
- 上下文不连贯

就不用。

## 3. 输入

最低输入：

**一篇可读的参考文案。**

支持：

- 直接粘贴正文
- md / txt 文件
- 可读取文章链接
- 可提取正文的视频链接

可选输入：

- 目标作者
- 目标受众
- 行业 / 产品
- 平台
- 目标时长
- 转化目的
- 必留事实
- 禁用表达
- CTA

如果用户只给文案：

默认中文短视频口播，保留主题、核心观点和有效部分，篇幅原则上接近原稿。

如果用户说“只要文案”：

最终只输出正文。

`writing-dna-skill`

`lieflat-less-ai-tone`
：最终清理 AI 痕迹，但不得覆盖目标作者真实存在的稳定写法。

## 5. 作者 Skill 查找与回退

进入作者模式后：

1. 查找 `writing-{author}`。
2. 找到则完整读取 `SKILL.md`。
3. 按当前任务读取相关 references。
4. 如果没有 `writing-{author}`，先从生产表按作者筛选 5–8 篇完整原文，建立仅供本次任务使用的临时作者校准卡。
5. 临时校准卡必须包含：内容类型、问题定义、结构、推进、论证、语气、句长、收尾与明显禁用写法。
6. 不得把临时校准卡说成已经生成或安装的作者 Skill。
7. 只有当 `account-distill` 真实可用且用户明确要求创建 / 更新作者 Skill 时，才调用它；完成后再回到改写任务。

禁止：

作者 Skill 不存在时，凭模型印象声称“按这个作者改”；或在未获授权时自动创建作者 Skill。

## 6. Writing DNA 联动

如果当前环境安装了：

`writing-dna-skill`

并且目标作者存在对应 Writing DNA 产物，则在写作前执行风格校准。

### 6.1 优先读取

至少读取：

- `Writing-DNA.md`
- `语言DNA.md` / `language-dna.md`
- `文章结构模板.md` / `structure-patterns.md`
- `写作视角与认知框架.md` / `cognitive-framework.md`

如果当前交付包含：

- 图文排版
- 视觉脚本
- 配图建议
- 画面结构

再读取：

- `视觉风格指南.md` / `visual-style-guide.md`

纯口播文案不强制加载视觉层。

### 6.2 原文校准

如果 Writing DNA 目录中有 `raw/`：

从中选择与当前任务**体裁和题材最接近的 5 篇完整原文**通读。

如果没有 raw，但飞书已有完整作者原文：

用飞书中最相关的 3–5 篇完整原文完成等价校准。

### 6.3 Writing DNA 的作用

它主要负责补足：

- 高频词与句式
- 句长分布
- 标点习惯
- 段落呼吸
- 内容类型对应结构
- 选题切入
- 素材使用方式
- 核心认知与判断倾向

它不是：

重新蒸馏作者。

也不是：

每次改写都重新分析 20 篇。

### 6.4 规则冲突

冲突时按下面处理：

**事实层：**

用户明确事实 / 当前原稿真实事实
>
第三方可验证事实
>
作者历史内容

**写作层：**

用户本次明确要求
>
当前内容本身的逻辑与真实性
>
匹配当前内容类型的作者结构
>
作者语言与节奏 DNA
>
作者认知框架

### 6.5 与去 AI 味冲突

如果 `lieflat-less-ai-tone` 的规则与作者真实 DNA 冲突：

**作者真实 DNA 优先。**

例如：

作者本来稳定使用破折号、重复句、短促句、强反问，
这些不是 AI 痕迹，不应被清理掉。

详细协议见：

`references/author-dna-integration.md`

## 7. 第一步：拆解原稿

建立内部 Content Card：

- 主题
- 目标受众
- 观众当前处境
- 看完能得到什么
- 核心观点
- 必留事实
- 原作者经历 / 用户经历 / 第三方案例 / 未核实断言
- 第一语句
- Hook 机制
- 开头承诺
- 文案逻辑
- 内容框架
- 中段推进
- 使用过的对比
- 条件规则
- 论证方式
- 收尾方式
- 已经优秀、应该保留的部分

### 三个概念必须分开

黄金开头：
最先听到的内容。

Hook：
继续看的理由。

结构：
全文怎样一步步推进。

不能混成一个标签。

---

## 8. 第二步：建立事实白名单

改写前必须建立内部 Fact Ledger。

分三类：

### Confirmed Facts

用户明确提供、当前原稿明确成立、或可靠来源已经确认的事实。

可以直接使用。

### Allowed Inferences

从 Confirmed Facts 可以保守推出，但不能放大确定性的内容。

必须保留：

可能、通常、适用于、在某些情况下等限定。

### Prohibited Inventions

禁止自行补：

- 收入
- 客户
- 销量
- 转化率
- 排名
- 认证
- 功效
- 测试结果
- 价格优惠
- 用户数量
- 第一人称经历
- 保证结果

没有真实案例时：

允许明确标注为“假设示例”，不能伪造“我有个客户”。

---

## 9. 第三步：自动判断改写强度

内部自动选择：

### LIGHT｜轻改

适用：

原稿已经成立，只需要改善局部口播、节奏、少量结构。

通常保留：

原有结构 + 原有推进。

### MEDIUM｜中改

适用：

主题和核心逻辑成立，但开头、推进、论证或收尾有明显优化空间。

通常：

保留核心价值，重新组织部分结构。

### REBUILD｜重构

适用：

原稿结构本身明显限制表达效果。

允许：

只保留主题、事实和核心观点，重新设计全文。

### 判断原则

不是用户没说就永远中改。

Agent 根据原稿质量自动决定。

只有用户明确指定强度时，才覆盖自动判断。

最终默认只输出**一篇最佳稿**。

用户要求 A/B 或多个版本时，再输出多个强度版本。

---

## 10. 第四步：素材库 / 作者样本检索

完整执行 `references/production-library-routing.md`。

核心顺序固定为：

1. `选题与借势库`：理解母问题、用户点击理由和外部势能。
2. `爆款文案拆解库`：精读最相关的 3–5 篇完整原文。
3. `爆款规律与改写组件库`：只在原稿存在明确缺口时选择 0–2 个组件。

不得倒过来先找高频组件，再寻找能够证明它的样本。

指定作者时先限制作者范围，再判断同母问题、同内容类型和同目标；不得用跨作者高频模式覆盖目标作者真实写法。

### 完整阅读要求

关键样本必须阅读完整 `原文 / 文案`。

不能只看：

- 标题
- 黄金开头
- Hook机制
- 内容结构
- 可复用机制
- AI 总结字段

AI 字段只负责索引和辅助判断。

三张生产表中的结构、机制和 Agent 指令同样只是候选。最终必须回到 `完整原文` 与当前输入稿比较。

| 开头 |  |  |  |  |
| Hook |  |  |  |  |
| 字数 |  |  |  |  |
| 信息密度 |  |  |  |  |
| 句长 |  |  |  |  |
| 段落 |  |  |  |  |
| 标点节奏 |  |  |  |  |
| 语气 |  |  |  |  |
| 对比 |  |  |  |  |
| Decision Rules |  |  |  |  |
| 逻辑 |  |  |  |  |
| 框架 |  |  |  |  |
| 推进 |  |  |  |  |
| 论证 |  |  |  |  |
| 收尾 |  |  |  |  |

普通模式：

把“作者 DNA”换成“素材库候选机制”。

### 修改标准

任何修改至少改善一项：

- 真实性
- 理解速度
- 继续观看理由
- 信息推进
- 论证完整度
- 口播自然度
- 记忆点
- 全文一致性
- 作者一致性

否则不改。

## 12. 第六步：生成完整初稿

先确定：

**全文最终要兑现的一句话是什么。**

然后再写：

开头
→ Hook
→ 推进
→ 论证
→ 方法 / 判断
→ 收尾

每一段至少承担一个新功能：

- 提出问题
- 给新信息
- 解释原因
- 给证据
- 给动作
- 建立判断标准
- 推进到下一阶段

如果只是换句话重复：

删除或压缩。

## 13. 作者模式的写作重点

作者模式不是复制口头禅。

真正优先级：

1. 问题怎么定义
2. 怎么判断
3. 怎么组织
4. 怎么推进
5. 怎么对比
6. 怎么论证
7. 怎么给边界和规则
8. 怎么表达
9. 具体措辞

### Tone DNA

不能只总结：

“口语化”“犀利”“专业”。

需要落实：

- 确定程度
- 第二人称
- 命令语气
- 反问程度
- 情绪强度
- 幽默 / 吐槽 / 自嘲
- 开头 / 中段 / 结尾的语气变化

### Contrast DNA

优先学习：

作者什么时候使用对比、用什么对象对比、对比承担什么功能。

不是为了“像”而强行制造冲突。

### Decision Rules

检查是否存在：

- 如果 X → Y
- 先 X → 再 Y
- 不要 X → 而要 Y
- 只有 X → 才 Y
- 达到 X → 再放大
- 超过 X → 停止

必须区分：

稳定判断原则

和

平台当时的临时参数。

## 14. 禁止移植的内容

不得把作者样本中的：

- 个人经历
- 收入
- 业绩
- 客户
- 公司
- 产品成绩
- 对话
- 独家案例
- 原创模型归属

变成用户自己的第一人称事实。

允许迁移：

- 结构
- 判断方式
- 推进逻辑
- 论证机制
- 节奏
- 表达机制

不允许：

换人名、换金额、换平台，就把别人的经历伪装成新故事。

## 15. 第七步：调用去 AI 味

完整读取并实际应用：

`lieflat-less-ai-tone`

不能只输出“已去 AI 味”。

清理范围：

只处理规则清单明确命中的 AI 痕迹。

不得改变：

- 事实
- 限定词
- 核心观点
- 论证关系
- 当前结构
- 目标作者稳定 DNA

---

## 16. 第八步：Author Authenticity Audit

作者模式在去 AI 味后必须再执行一次作者一致性审计。

对照：

- `writing-{author}`
- Writing DNA 分层产物（如有）
- 本次精读的真实样本

检查：

### 内容决策

- 问题定义像不像
- 判断方式像不像
- 推进逻辑像不像
- 对比使用像不像
- 条件规则像不像
- 收尾决策像不像

### 语言指纹

- 字数区间
- 句长分布
- 段落节奏
- 标点习惯
- 语气
- 第二人称 / 命令语气
- 常见表达倾向

### Negative DNA

有没有加入作者明显不常用的：

- 通用爆款套路
- 夸张 CTA
- 虚假反常识
- 强行三点式
- 鸡汤式升华
- 人为制造焦虑

### 修正原则

发现“不像”时：

只修导致偏差的部分。

不要整篇重新洗一遍。

如果偏差来自 `lieflat-less-ai-tone`：

恢复作者真实特征。

如果偏差来自作者 Skill 本身：

记录问题，交给 `account-distill` 的 correction / evolution 流程。

## 17. 标题与话题

基于最终正文生成：

- 1 个推荐标题
- 2 个备选标题
- 3–5 个相关话题标签

标题可以走：

- 痛点
- 结果
- 好奇
- 判断
- 具体问题

但不能强凑反常识。

标题不能承诺正文没有交付的东西。

## 18. 最终 QA

完整检查见：

`qa/final-check.md`

最低要求：

- 原主题没有被改丢
- 事实没有被移植或伪造
- 选中样本已读完整原文
- 作者模式已加载作者 DNA
- 可用时已经使用 Writing DNA 做二次校准
- 改写强度选择合理
- 每个重要修改有明确收益
- Hook 有兑现
- 正文持续推进
- 没有套高频公式
- 去 AI 味没有洗掉作者真实特征
- 作者模式通过 Authenticity Audit
- 标题与正文一致

## 20. 用户纠正

如果用户说：

- 不像跨海
- 这个语气不对
- 他不会这么说
- 这个开头不像
- 这个节奏不对

不要只是重写。

定位属于：

- 字数
- 句长
- 段落
- 标点
- 语气
- 开头
- Hook
- 对比
- Decision Rule
- Logic
- Framework
- Progression
- Evidence
- Ending

然后：

1. 回看当前使用的作者 DNA。
2. 回看真实作者样本。
3. 判断是：
   - 当前应用错误
   - 内容类型判断错误
   - 作者 Skill 规律错误
4. 修正文案。
5. 若确认作者 Skill 有问题，交给 `account-distill` 增量纠正。

## 21. 最终原则

普通模式：

**素材库提供可比较的真实写法，不提供固定公式。**

作者模式：

**`writing-{author}` 提供稳定规则，`writing-dna-skill` 提供二次风格校准，真实原文负责验证，当前原稿负责这一次的事实和主题。**

最终目标不是：

“把这篇稿子改得像作者以前写过的某一篇。”

而是：

**面对一个新的题，按照这个作者真实历史语料中稳定的判断、结构、推进、对比、节奏与语言习惯，重新完成一篇属于当前任务的新文案。**
