# Production Library Routing

本参考规定 `baokuan-rewrite` 如何使用飞书中的写作生产层。它们是 Agent 的检索与比较数据，不是要求用户逐列阅读的报告。

## 三张表分别回答什么

### 选题与借势库

回答：

- 参考文案表面在讲什么？
- 去掉人物、热点、平台或案例后，真正的母问题是什么？
- 用户为什么愿意点开？
- 外部势能承担了多少注意力？
- 同一个母问题还能从什么对象、阶段或立场继续写？

优先读取字段：

- `Topic Card ID`
- `别人怎么写（标题）`
- `作者`
- `原选题切口`
- `去势后的母问题`
- `用户为什么点开`
- `借势类型`
- `借势对象`
- `外部势能依赖`
- `去势后是否仍成立`
- `别人采用的写法`
- `别人开头原句`
- `source_record_id`

这张表只负责理解和寻找候选，不直接决定最终结构。

### 爆款文案拆解库

回答：

- 这篇原文前三句具体怎么写？
- 第二段如何承接？
- 中段怎样持续推进？
- 用什么方式论证？
- 最后怎样收束？
- 哪些事实、人物或经历不能移植？

优先读取字段：

- `Breakdown ID`
- `作者`
- `标题`
- `完整原文`
- `前三句原文`
- `开头机制`
- `开头为什么有效`
- `承接原文`
- `中段推进原文`
- `原文结构拆解`
- `可套用结构公式`
- `论证方式`
- `表达动作`
- `结尾原文`
- `变量槽`
- `不可照抄/失效条件`
- `source_record_id`

完整原文是判断依据；拆解字段只帮助定位，不得替代阅读。

### 爆款规律与改写组件库

回答：

- 当前稿件某个明确问题有没有可比较的结构组件？
- 该组件怎样执行？
- 有哪些真实原句支持？
- 什么时候不适用？

优先读取字段：

- `Component ID`
- `组件名称`
- `组件维度`
- `结构公式`
- `变量槽`
- `Agent执行指令`
- `典型原句1–3`
- `适用条件`
- `不适用条件`
- `证据等级`
- `反例/失效检查`
- `source_record_ids`

组件库没有修改优先权。原稿已经更合适时，组件选择数量为 0。

## 检索顺序

### 普通素材库模式

1. 从输入稿建立 Content Card。
2. 在选题与借势库中按母问题、用户处境、内容目标与借势类型初选 4–8 条。
3. 取得这些记录的 `source_record_id`，在爆款文案拆解库中寻找相同记录及同问题、同内容类型的候选。
4. 去重后保留最相关的 3–5 篇，完整阅读 `完整原文`。
5. 先判断原稿在开头、推进、论证、收尾中的具体缺口。
6. 只有存在明确缺口时，才从组件库选择 0–2 个组件参与比较。
7. 对每个部分作 `KEEP / ADAPT / REBUILD` 决策。

### 指定作者模式

1. 在选题与借势库和爆款文案拆解库中先筛选 `作者 = 目标作者`。
2. 在该作者范围内，再按母问题、内容类型和任务目标排序相关性。
3. 精读 3–5 篇；若没有持久化作者 Skill，则精读 5–8 篇并建立临时作者校准卡。
4. 组件库只提供结构候选，不得用跨作者高频组件覆盖目标作者真实写法。

## 相关性判断

按以下顺序判断，不使用单一关键词命中代替语义判断：

1. 是否解决同一个母问题。
2. 是否面对相近的用户处境。
3. 内容目标是否一致：解释、诊断、教程、案例、转化或观点。
4. 事实与论证条件是否相近。
5. 内容类型和篇幅是否相近。
6. 指定作者时，是否确为该作者真实样本。

匹配不足时少选，不凑数。不得因为标题里都出现“AI”“普通人”“爆款”就判为相关。

## 与原稿比较

每个候选只允许贡献一种或几种明确机制，例如：

- 开头的信息缺口
- 第二段的承接动作
- 问题链推进
- 案例论证
- 判断标准
- 收尾方式

禁止把多篇候选的“最强局部”机械拼接成一篇声音不一致的稿子。

修改必须至少提升一项：真实性、理解速度、继续观看理由、信息推进、论证完整度、口播自然度、记忆点或全文一致性。无法说明提升时保留原稿。

## 读取方式

使用 `lark-base`，身份优先 `--as user`。预计每张表不足 500 条时可一次导出所需字段到 NDJSON 后在本地筛选；按作者精确筛选时也可使用服务端条件。

不要每次把三张表全部载入上下文。先读最小字段完成候选筛选，再读取最终候选的完整原文和相关组件。

如果生产表不可用：

1. 回退到原始内容事实表。
2. 读取真实字段和完整原文。
3. 明确说明本次使用了回退路径。
4. 不得凭空声称已经检索生产表。
